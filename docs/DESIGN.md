# 设计文档

本文记录"为什么是这样"，而不是"是什么"——后者看 README 与源码注释。

## 1. 问题的本质

让 agent 持续工作，表面上是个"自动发消息"的问题，实际上是个**判断问题**：

> 谁来回答"活到底干完没有"？

如果这个问题答错，会出现两种失败：

- **误判完成**（更糟）：agent 说了句"任务已完成"，监工信了，收工。主人醒来发现什么都没干。
- **误判未完成**：活干完了还在抽鞭，烧钱烧时间，甚至把已经完成的东西改坏。

所以整个项目的重心是**把判定建立在可验证的证据上**，而不是"再发一条消息"。

## 2. 三层判定（从硬到软）

```
第一层：验收命令的真实退出码        ← 最硬，无法伪造
第二层：方案复选框的勾选状态         ← 人写的合同，agent 自己勾
第三层：工作区改动指纹（git + 文件）  ← "它到底动没动手"
————————————————————————————————
判不了 → needs-human（交还给人）      ← 绝不用"感觉"补上
```

规则判定器（`src/judge/rule.mjs`）就是这三层的直译。LLM 判定器（`judge/llm.mjs`）拿到的是
同一批证据，只是多了一层语义理解（例如"它说完成了，但验收标准第 3 条没有对应证据"）。
`chain` 判定器让规则先行、必要时才升级——这既省钱，也比"每轮都问模型"稳定：
绝大多数轮次（"还有待办没勾 → 继续"）根本不需要模型。

### 判定顺序为什么这样排

```js
1. agent 显式宣告受阻（<!-- CW:BLOCKED ... -->）      → blocked
2. 卡死检测（连续 N 轮回答+证据都没变）                → blocked（换成"换条路"的鞭子）
3. 验收命令失败                                       → continue（把失败输出塞进鞭子）
4. 还有未勾选的待办                                   → continue（指向具体条目）
5. 全勾选 + 验收全绿                                  → done
6. 全勾选但没有验收命令                               → needs-human（不猜）
7. 方案没有任何结构                                   → needs-human（并给出改方案的建议）
```

把"卡死"排在"还有待办"之前是刻意的：如果 agent 连续三轮回答一模一样、工作区一动不动，
再复述一遍待办清单是没用的——它需要的是一句"你卡住了，换条路，或者明确说你需要什么"。
（这一条是实测踩出来的：早期版本会在卡死状态下一直复述待办，直到轮次上限。）

## 3. 时间与状态：谁等谁

适配器分两类，这个区分决定了引擎的等待逻辑：

| 模式 | 含义 | 例子 |
|---|---|---|
| `foreground` | `whip()` 自己把 agent 跑完一整轮，返回时新回答已经产生 | `codex exec resume`、`dsh --profile headless`、通用 CLI |
| `inject` | 只是往活着的会话里塞一句话，agent 之后才开始干活 | 拟人通道、Cursor hook、DSH HTTP 注入 |

- `foreground`：抽完直接进入下一轮判定。
- `inject`：抽完必须**等 agent 开工、再等它收工**（`waitForNewAnswer`），否则会在它还在写的时候
  抢焦点/重复注入。

主循环在判定之前也会先等 agent 空闲（`waitForTurnEnd`）——**绝不在它正说话的时候插嘴**。
这是"多轮对话被搅乱"最常见的原因。

## 4. 方案文档是"活"的

早期实现只在启动时解析一次方案文档，结果 agent 勾掉的复选框监工永远看不见，
判定一直停在"0/4 未完成"——最后靠"无进展熔断"停下（行为正确，但根因是错误的）。

现在**每轮都重读**方案文档：它的 sha 变化会被记进日志，勾选进度就是"进展"的权威来源。
方案文档因此不只是"输入"，而是一份**双方都在写的共享状态**：人写目标与验收标准，agent 勾进度，
监工读它做判断。这也是我们推荐 agent"做完一项就勾掉一项"的原因。

## 5. 证据采集的成本控制

验收命令（`npm test` 之类）可能很慢，所以 `evidence.mjs` 里做了输入指纹缓存：

```
输入指纹 = hash(git HEAD, git status --porcelain 哈希, 方案文档 sha)
```

只要输入没变、且上一轮是**通过**的，就直接复用结果（`cached: true` 会写进日志，避免自欺）。
失败的命令永远重跑（因为我们要的是"现在绿了没有"）。`evidence.verifyEveryRound` 可以强制每轮都跑。

## 6. 适配器的"不猜"原则

读别人家的数据是这件事里最容易出错的部分，所以每个适配器都遵守：

- **只读**：会话库一律 `readOnly` 打开；sqlite 是 WAL 的还会把 `db + -wal + -shm` 拷到临时目录再读
  （只读打开会读到旧快照或直接失败，且 `DatabaseSync` 是惰性打开——构造不抛错、第一条语句才抛）；
- **不猜格式**：读不到就返回 `error/unknown`，让引擎知道"数据不可信"，而不是拿半个字段硬凑；
- **记录来源**：快照里带 `readVia`（磁盘/剪贴板/UIA）之类的元信息，报告里能看出判定依据从哪来。

各家格式的实测细节见 [`docs/recon/`](recon/)：
- [`dsh-session-storage.md`](recon/dsh-session-storage.md)：多帧 zstd、事件词表、`turn/start|end` 折叠、
  并发读安全性（丢半截尾帧永不产生半行）；
- [`dsh-control-surfaces.md`](recon/dsh-control-surfaces.md)：headless 无 resume、`POST /api/session.prompt`
  信封、ACP、goal-round-driver、SDK JSON-RPC；
- [`codex.md`](recon/codex.md)：`threads` 索引、rollout 的 mtime 不更新（只有 ctime 走）、
  `user_message` 没有 turn_id；
- [`opencode.md`](recon/opencode.md)：事件溯源 + 投影、`step-finish.reason === 'stop'` 才是真的收工、
  `run -c` 不按 cwd 过滤；
- [`cursor.md`](recon/cursor.md)：`cursorDiskKV` 键布局、`stop` hook 的 `followup_message`、
  以及"conversation-search.db 滞后 ≥1 轮不能用"这类反向结论。

## 7. 拟人通道：把危险的部分单独围起来

抢焦点、打字、回车——这是本项目里唯一"能对外界造成不可逆影响"的动作（可能把消息发错人、
可能覆盖主人的草稿）。所以它不是散落在代码里，而是集中在 `src/adapters/human-sim.mjs` +
`src/ui/win/ui-driver.ps1`，并且每次注入都要过三道保险（空闲、焦点回读、内容校验）。

读的部分同理：优先让**别的适配器读磁盘**（`options.readerAdapter`），
读不到才退化成剪贴板整段捞，再不行才用 UIA。因为"整段捞文本 + 自己切出最后一条回答"
本质上是有损的启发式，能不用就不用。

## 8. 报告：无人值守工具的信用

一个跑了 8 小时的无人值守进程，如果最后只留下一行 "done"，主人是无法信任它的。
所以收尾必须给一份**能在 30 秒内读完的交代**（`CW-REPORT.md`）：

- 为什么停（含每种停止原因的人话解释）；
- 每一轮：判定、置信度、理由、**抽出去的那一鞭原文**；
- 还剩什么没做（未勾选项）；
- 建议下一步（"预算用完了就调大 X"、"判定不了是因为方案缺验收标准"）。

配合 `.cyber/journal.jsonl` 的完整事件流，主人在需要时可以逐轮回放整个监工过程。

## 9. 已知取舍与未做的事

- **没有实现**：Windows 之外的拟人通道（接口已留）、OCR 读取（截图识别）、
  DSH 的 ACP/SDK JSON-RPC 通道（`docs/recon/dsh-control-surfaces.md` 已把协议摸清，但优先级低于
  已验证的 headless 与 HTTP）、多 agent 并行监工（一个监工进程监一个会话）。
- **刻意不做**：替主人批准危险操作（`guard.autoApprove` 默认 false 且会告警）、
  自动提交/合并代码、修改 agent 的会话数据。
- **可能骗过监工的**：验收命令本身被 agent 改坏（例如把测试改成永远通过）。
  缓解手段是 `git diff` 证据 + 方案里的"禁止改动"章节；彻底解决需要人看一眼报告——
  这也是报告存在的另一个理由。
