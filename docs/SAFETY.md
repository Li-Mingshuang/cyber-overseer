# 安全模型

赛博监工是一个**能替你对别的程序说话、替你做判断**的工具。它跑在无人值守场景里，
意味着出错时没人当场拉住它。所以这里把风险、缓解手段和"你必须自己决定的事"讲清楚。

## 1. 它最坏能干什么

| 能力 | 最坏情况 |
|---|---|
| 往 agent 里注入文本 | 让 agent 去做你并不想做的事（越权改代码、删数据、发外部请求） |
| 拟人通道抢焦点打字 | 把内容打进**错误的窗口**（比如打到你的聊天窗口里发出去） |
| 运行验收命令 | 执行你在配置里写的命令（本身是你授权的，但命令可能有副作用） |
| 读会话数据 | 读取 agent 的完整对话历史（含可能敏感的内容） |
| 写报告/日志 | 把 agent 的回答写进 `CW-REPORT.md`（如果你提交它，内容就进版本库了） |

它**不能**做的事（设计上就做不到）：批准 agent 的危险操作（默认不点"同意"）、
修改 agent 的会话数据、自动提交/推送代码、绕过操作系统的权限。

## 2. 四道默认防线

### 2.1 判定不被"漂亮话"骗

默认的判定顺序里，**验收命令的真实退出码排在最高优先级**，高于 agent 的任何自述：

```
验收命令失败 → continue（哪怕 agent 说"已经全部完成"）
全勾选但没有验收命令 → needs-human（不猜）
无法解析模型输出 → needs-human（绝不退化成 done）
```

所以要真正安全地判"完成"，请在配置里写 `evidence.verify`。没有验收命令时，
监工会在关键节点把决定交还给你——这是刻意的，不是缺陷。

### 2.2 拟人通道的三道保险

1. **空闲保险丝**（`guard.requireHumanIdleMs`，默认 120 秒）：
   系统级键鼠空闲不到阈值就**不动手**（会等，等到超时就放弃这一鞭）。
   这条保险的语义就是项目标题："**在人类主人休息时**才抽鞭"。**不要把它设成 0。**
2. **焦点回读确认**：抢焦点后用 `GetForegroundWindow` 回读，**必须等于目标窗口**才继续；
   否则立刻放弃（不会出现"焦点没抢到却把字打进了别的窗口"）。
3. **回车前内容校验**：粘贴完先 `Ctrl+A`/`Ctrl+C` 把输入框内容读回来与原文比对，
   一致才按回车；不一致就直接放弃（内容留在输入框里，由你人工处理）。
   **错误的指令永远不会被发出去。**

另外：`clearComposer` 默认 false —— 监工**不会**清空输入框里已有的内容（那可能是你的草稿）。

### 2.3 无人值守的预算与熔断

| 护栏 | 默认 | 挡住什么 |
|---|---|---|
| `maxRounds` | 24 | 无限抽鞭烧钱 |
| `maxWallClockMs` | 10 小时 | 忘记关掉 |
| `maxStallRounds` | 3 | agent 卡死时继续烧钱 |
| `maxBlockedRounds` | 2 | 受阻后反复无效重试 |
| `maxCostUsd` | 未设 | 判定器花费（模型按价目表估算） |
| `quietHours` / `workWindow` | 未设 | 你不在时/你在时的工作时段控制 |
| `.cyber/PAUSE` | — | 随时喊停（`cw pause`，甚至 `touch` 一个文件就行） |

### 2.4 只读别人的数据

- 所有会话库（`state_5.sqlite`、`opencode.db`、`state.vscdb`）都以 **readOnly** 打开；
- WAL 库在只读目录下会把 `db + -wal + -shm` 拷到临时目录再读（不改原库）；
- 监工只写自己的 `.cyber/`（日志、状态、信箱）与项目根的 `CW-REPORT.md`；
- 拟人通道读剪贴板后**会还原**剪贴板内容；抢焦点后**会还回**原来的前台窗口。

## 3. 你必须自己决定的事

### 3.1 审批绕过

无人值守必然要面对 agent 的审批机制。监工不会替你点"同意"，但**你可能会在 agent 侧关掉它**：

- codex：`-c approval_policy=never`
- DSH headless：`DSH_PERMISSION_MODE=danger-full-access`（等价于 approval policy = never）
- opencode：`--auto`

这三者都意味着"agent 可以不经确认就执行危险操作"。请只在你能接受这个代价的项目上使用，
并且优先用沙箱更强的档位（`workspace-write` 而非 `danger-full-access`）。

### 3.2 验收命令本身可能被改坏

如果 agent 有权限改你的测试，它可以把 `npm test` 改成永远通过。缓解手段：

- 在方案文档里写明"禁止修改 X"（监工会把它放进判定上下文）；
- 看 `CW-REPORT.md` 里的 `git diff --stat`（改动是否碰到了测试/CI）；
- 让验收命令包含"外部"检查（例如 `node verify.mjs` 里的独立断言、真实 HTTP 调用）。

彻底的解法是有人在早上看一眼报告——这也是报告存在的理由之一。

### 3.3 会话数据里可能有敏感信息

监工读的是 agent 的完整对话（可能含密钥、内部链接、用户数据）。因此：

- `.cyber/` 与 `CW-REPORT.md` 已默认进 `.gitignore`（历史事件 + 报告可能含敏感片段）；
- `journal.storeAnswers` 默认 **false**（只存回答摘要与哈希）；
- 如果你要分享报告，先扫一眼——`CW-REPORT.md` 里会包含最后一次回答的尾部原文。

### 3.4 Cursor 钩子会常驻在你的项目里

`cw hooks install cursor` 会写 `.cursor/hooks.json`：Cursor 每个回合结束都会调用监工 CLI。
这意味着**判定（可能包含一次 LLM 调用）会在每回合后发生**。如果你不想让它常驻，
用 `cw hooks` 装完后随时删掉那个文件即可（Cursor 会热重载）。

## 4. 关于 DSH 的一个真实安全发现

逆向 DSH 控制面时（见 [`recon/dsh-control-surfaces.md`](recon/dsh-control-surfaces.md)）发现：

> 用户的 DSH web profile 把 webserver 绑到了 `0.0.0.0`（绕过了 CLI 的 `--host 0.0.0.0` 守卫），
> 而 `/api` **没有认证层**（DSH 源码自述 "not an auth layer"）。

后果：**同一局域网内的任何机器**都可以无凭证调用 `session.prompt`（往你的会话里插话）、
`goals/resume`、`commands/execute`（执行命令）。

缓解建议：
1. 把 web profile 的 host 改回 `127.0.0.1`（除非确实需要手机访问）；
2. 需要跨机访问时，用 SSH 隧道而不是直接暴露；
3. 本项目的 DSH HTTP 注入通道**硬编码拒绝**非 `127.0.0.1`/`localhost` 的地址，
   就是基于这个发现。

（本项目的文档与代码里不含任何密钥；逆向过程中发现的明文凭据位置只在报告里作为"事实"提及，
未复制内容。建议相关工具的使用者也检查一下自己的凭据存放方式。）

## 5. 报告安全问题的路径

发现漏洞请开 issue（或私下联系维护者）。请不要在 issue 里贴真实的会话内容、密钥或内网地址。
